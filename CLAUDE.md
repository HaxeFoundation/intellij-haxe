# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project
The official IntelliJ Haxe plugin: language support, completion, semantic analysis, navigation,
HXML / OpenFL build integration, haxelib management, and an hxcpp debugger for IDEA-based IDEs
(2023+). Targets IDEA Ultimate by default — see `platformType = IU` in `gradle.properties`.

## Rules
1. Do not use `cd`. Stay at the project root and use absolute paths.
2. When investigating a bug, write a failing test that reproduces it first, then fix until green.
3. Multiple agents may share this workspace. If you see surprising build failures or edits you
   do not recognise, do not blindly revert or overwrite — flag it to the developer.
4. Use plain, natural language. Be concise and easily understandable, no buzzwords.
5. Run only the test(s) relevant to your change. Run the full suite only as a final verification.
6. Do not commit anything yourself. When you are done, list exactly which files you have edited or created. Make sure you don't list the diff but actually list only the files you've touched - other agents may have made changes at the same time. Then give the dev a very short, non-ai sounding natural language commit message without buzzwords, high level.
7. The developer sometimes pastes Haxe code from other (closed-source) projects to explain or
   reproduce a bug. Never copy that code, its type names, field names, or domain wording into
   this repository. Reduce it to the language feature being tested and write tests and fixtures
   with completely generic names.

## Common commands

All commands run from the project root via the Gradle wrapper.

| Task | Command |
| --- | --- |
| Full build with tests + plugin verification | `./gradlew clean build verifyPlugin` |
| Build the plugin ZIP without running tests | `./gradlew buildPlugin` |
| Run all tests | `./gradlew test` |
| Run one test class | `./gradlew test --tests "com.intellij.plugins.haxe.ide.HaxeSemanticAnnotatorTest"` |
| Run one test method | `./gradlew test --tests "com.intellij.plugins.haxe.ide.HaxeSemanticAnnotatorTest.testRemoveOverride"` |
| Launch a sandbox IDE with the plugin loaded | `./gradlew runIde` |
| Generate parser/lexer sources only | `./gradlew generateSources` |
| Remove `src/main/gen/` outputs | `./gradlew cleanGenerated` |
| Reset the cached IDEA download if corrupted | `./gradlew removeIdeaCache` |
| Recreate IDEA run configurations | `./gradlew regenerateRunConfigurations` |

Override the target IDE for a one-off build with `-PtargetVersion=<VERSION>`. The persistent
choice lives in `gradle.properties` (`platformVersion`, `platformType`, `platformPlugins`,
`pluginSinceBuild`, `pluginUntilBuild`).

The resulting plugin is written to `intellij-haxe-<platformVersion>.zip` at the project root.

## Toolchain
- JDK: Java 21 source/target, Kotlin JVM toolchain 21, `javaVersion = 25` in properties.
- Lombok is on. `lombok.config` maps `@CustomLog` to `Logger.getInstance(...)` from the IntelliJ
  Platform — use `@CustomLog` on a class to get a `log` field wired to IDEA's logger.
- Gradle 9.4.1 via the wrapper. The IntelliJ Platform Gradle Plugin manages the IDEA download.

## Module layout
- `src/` — main plugin module (root Gradle project, `:Haxe-plugin`). All IDE-facing features.
- `common/` — code shared between the IDE plugin and the JPS plugin.
- `jps-plugin/` — JPS (JetBrains Project System) hooks that run inside IDEA's external build
  process, not inside the IDE itself.
- `hxcpp-debugger-protocol/` — wire format for the hxcpp debugger.
- `src/main/gen/` — generated parser/lexer/PSI output of `generateSources`. Not checked in.

## High-level architecture

### Language pipeline (`com.intellij.plugins.haxe.lang`)
Three grammar pairs feed three lexer/parser sets, all regenerated by `generateSources`:
- Haxe: `lang/parser/haxe.bnf` + `lang/lexer/haxe.flex`
- HXML build files: `buildsystem/hxml/parser/hxml.bnf` + `buildsystem/hxml/lexer/hxml.flex`
- Haxe metadata (`@:meta(...)`): `metadata/parser/metadata.bnf` + `metadata/lexer/metadata.flex`

`lang/psi` holds the PSI element interfaces and IntelliJ-compatible impls/stubs that the
generated parser produces.

### Semantic model (`com.intellij.plugins.haxe.model`)
A richer abstraction layered on top of the PSI tree — `HaxeClassModel`, `HaxeMethodModel`,
`HaxeFieldModel`, `HaxeEnumModel`, etc. Most inspections, completion, navigation, and the
semantic annotator query the model rather than walking PSI directly. Two key subpackages:
- `model/type` — type resolution (`HaxeTypeResolver`, `HaxeGenericResolverUtil`,
  `HaxeTypeUnifier`). Most "what type is this expression?" logic lives here.
- `model/evaluator` — expression evaluator (`HaxeExpressionEvaluator*`). Drives inferred-type
  hints, the semantic annotator, and call-expression analysis under `callexpression/`.

### IDE integration (`com.intellij.plugins.haxe.ide` and siblings)
- `ide/` — completion, refactoring, go-to, find-usages, parameter info, inlay hints, live
  templates, formatter, etc.
- `codeInsight/`, `codeInspection/` — intentions and inspections.
- `editor/` — typed handlers, brace matchers, and other editor-only behaviour.
- `haxelib/` — discovery and resolution of haxelib libraries on the system.
- `runner/`, `compilation/`, `execution/` — run configurations and compiler integration.
- `buildsystem/` — HXML, OpenFL / Lime, NMML build wiring.
- `frameworks/` — framework-specific support (Flash / AS3, OpenFL, etc.).
- `metadata/` — Haxe `@:meta` metadata parsing and indexing.

### Tests
- Test sources: `src/test/java/com/intellij/plugins/haxe/...`.
- Test fixtures: `src/test/resources/testData/<feature>/...` — `.hx` files plus expected output.
- Semantic-annotator tests (`HaxeSemanticAnnotatorTest`, `HaxeSemanticAnnotatorHaxe5Test`) load
  `.hx` files from `testData/annotation.semantic/` and assert error / warning markers. When
  adding a regression test for a semantic check, drop the `.hx` fixture there and add a
  `testXxx()` method following the existing pattern.
- `verifyPlugin` runs the JetBrains plugin verifier and gates releases — break it and CI fails.

## Working notes
- Generated sources live under `src/main/gen/` and are excluded from version control. If you
  see "cannot resolve symbol" errors only for parser / PSI classes after a fresh checkout, run
  `./gradlew generateSources`.
- `compileJava` and `compileKotlin` already depend on parser / lexer generation, so a normal
  `build` regenerates them automatically.
- The first build downloads the configured IDEA Ultimate distribution into `./idea/`. Repeated
  builds reuse it. If a download is corrupt, `./gradlew removeIdeaCache` resets it.
- Plugin descriptions for the JetBrains Marketplace come from `DESCRIPTION.md` (between the
  `<!-- Plugin description -->` markers) and `CHANGELOG.md`. Do not edit the description in the
  generated `plugin.xml` by hand — change `DESCRIPTION.md` instead.
